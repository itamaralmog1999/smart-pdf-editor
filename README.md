# 📄 MyDocs — עורך טפסים חכם

**עורכים תבנית פעם אחת, ממלאים בכל מכשיר, שומרים בדרייב של הלקוח ומייצאים PDF נקי.**

> שם זמני. כשתבחר שם סופי, מחליפים אותו ב-`index.html` וב-`js/drive.js` (ראו "שינוי שם").

*English: a browser-based smart form builder and filler (Hebrew/English, RTL). Documents are stored in the user's own Google Drive; no backend of yours is required.*

---

## ✨ מה זה

אפליקציית אתר סטטית (HTML, CSS ו-JavaScript בלבד, בלי שרת), שמארחים ב-GitHub Pages.

- **מצב עריכה:** בונים טופס מתאים, כמו מחברת.
- **מצב מילוי:** המשתמש רואה רק מה שממלאים, ללא כפתורי עריכה, עם ניווט בין עמודים וחלקים מתקפלים.
- **שמירה בדרייב:** כל לקוח מתחבר עם Google, והקבצים נשמרים בתיקייה בדרייב **שלו**.
- **PDF:** ייצוא מסודר עם שוליים, קווים לכתיבה, כותרות חוזרות וחתימות.

```
├── terms.html                    ← תנאי שימוש
├── allowed.json                  ← מיילים מאושרים (כקודים) ותוקף רישיון
├── README.md                     ← הקובץ הזה
├── css/
│   └── style.css                 ← כל העיצוב (עורך, מצב מילוי, PDF, לוח קבצים, התחברות)
└── js/
    ├── i18n.js                   ← טקסטים בעברית ובאנגלית
    ├── state.js                  ← נתוני המסמך, שמירה אוטומטית, VERSION
    ├── dom.js                    ← כלי עזר לבניית אלמנטים, ולוח החתימה
    ├── ui.js                     ← מצב עריכה
    ├── io.js                     ← ייצוא וייבוא, הצפנה, ניקוי מהמכשיר
    ├── print.js                  ← ייצוא PDF והערכת עמודים
    ├── fill.js                   ← מצב מילוי, ניווט וחלקים מתקפלים
    ├── drive.js                  ← Google Drive, סרגל קבצים, תבניות, נעילת מיילים
    └── main.js                   ← הפעלה ואזהרת אי-התאמה בין גרסאות
```

> **סדר הטעינה ב-`index.html` חשוב:** `i18n`, `state`, `dom`, `ui`, `io`, `print`, `fill`, `drive`, `main`. קובץ חדש נוסף לפני `main.js`.

## 🔐 חיבור ל-Google Drive (הגדרה חד-פעמית, שלך)

הלקוחות לא עושים את זה. הם רק לוחצים "התחברות עם Google" ומאשרים.

1. [console.cloud.google.com/projectcreate](https://console.cloud.google.com/projectcreate): יוצרים פרויקט.
2. [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com): **Enable**.
3. **Google Auth Platform** ← **Get started**: שם אפליקציה, מייל תמיכה, Audience: **External**.
4. **Data Access** ← Add or remove scopes ← `.../auth/drive.file` (ההרשאה היחידה שנדרשת).
5. **Audience** ← **Test users**: מוסיפים מיילים לבדיקה (כל עוד האפליקציה ב-Testing, רק הם יכולים להתחבר, עד 100).
6. **Clients** ← **Create client** ← Web application. תחת **Authorized JavaScript origins** כותבים רק את הדומיין, **בלי נתיב ובלי `/` בסוף**:
   `https://<משתמש>.github.io`
7. מעתיקים את ה-**Client ID** ומדביקים ב-`js/drive.js`:

```js
const GOOGLE_CLIENT_ID='123456789012-abcdefg.apps.googleusercontent.com';
```

> ה-Client ID גלוי בקוד בכוונה ואין בו סוד. **לעולם לא** מדביקים Client secret.

**לפני שמוסרים ללקוחות:** ב-**Branding** מזינים את הכתובות של `privacy.html` ו-`terms.html`. כשמעבירים מ-Testing ל-**In production**, ייתכן שגוגל תבקש אימות מותג (דומיין מאומת, דף בית ומדיניות פרטיות). כתובת `github.io` שייכת ל-GitHub ולא ניתנת לאימות כדומיין שלך, ולכן למוצר מסחרי כדאי דומיין משלך.

### איך זה עובד אצל הלקוח

1. נכנס לאתר ← "התחברות עם Google" ← מאשר (ב-Testing יראה אזהרת "לא מאומתת": Advanced ← המשך).
2. האתר יוצר בדרייב שלו תיקייה `MYDOCS-<המייל שלו>`. בטלפון הוא מוצא את אותה תיקייה לפי השם.
3. האתר רואה **רק קבצים שהוא יצר בעצמו** (הרשאת `drive.file`).

## 🛡️ הגבלת גישה: מיילים מאושרים

כברירת מחדל האתר פתוח (`REQUIRE_LOGIN=false`). כדי שרק מיילים שאישרת יוכלו להשתמש בו:

1. פותחים `admin/licenses.html` מהמחשב (בלחיצה כפולה). כותבים מיילים, בוחרים "תקף עד", לוחצים **צור**.
2. מדביקים את התוצאה ב-`allowed.json`, Commit ו-Sync.
3. **רק אחרי שהמייל שלך נמצא ברשימה**, ב-`js/drive.js` משנים `REQUIRE_LOGIN` ל-`true`.

> זו נעילה חלקית: הקוד צד-לקוח וגלוי. נעילה אמיתית מקבלים מ-**Test users** של גוגל (בזמן Testing) או מבדיקה בצד שרת (למשל Cloudflare Access, עד 50 משתמשים חינם, בדוק את התנאים העדכניים).
>
> מיילים נשמרים כקודים (SHA-256), ולא בגלוי.

## 🧭 שימוש

### מצב עריכה
- כפתורי **+** בתחתית ובין התאים מוסיפים תא בכל מקום.
- בסרגל כל תא: כיוון טקסט, **U** קו תחתון, **📌** תא שחוזר בכל עמוד, **📄** התחל בעמוד חדש, ▲▼ הזזה, ✕ מחיקה.
- **כותרת מתקפלת:** בתא כותרת מסמנים "חלק מתקפל במצב מילוי". כל מה שמתחתיה עד הכותרת הבאה יתקפל. אפשר גם "סגור כברירת מחדל".
- **שורות ריקות:** כמעט לכל תא יש שדה "שורות ריקות" שמודפסות אחריו. אפשר להקליד בהן.

### מצב מילוי
- כפתור **מצב מילוי** בסרגל. המצב נשמר עם המסמך, כך שייצוא שנעשה במצב מילוי נפתח במצב מילוי.
- אין כפתורי עריכה. בוחרים אפשרויות בלחיצה (○ ← ●), חותמים במסך קטן, ומנווטים לפי מספרי עמודים (הערכה).
- ▾/▸ ליד כותרת מכווצים או מרחיבים חלק, ו"כווץ הכל / פתח הכל" בסרגל.
- חלקים מכווצים עדיין **נכללים ב-PDF**.

### ייצוא PDF
**ייצוא PDF** פותח את חלון ההדפסה של הדפדפן ← **Save as PDF**. מומלץ לכבות Headers and footers. הנייר נקבע ל-A4 ושוליים 16 מ"מ למעלה ולמטה ו-14 מ"מ בצדדים.

### קבצים
- **ייצוא קובץ / ייבוא קובץ:** קובץ `.txt` שמכיל JSON (לבעיות טלפון שחוסם `.json`). הייבוא מקבל כל קובץ טקסט.
- **ייצוא מוצפן:** מצפין בסיסמה (AES-GCM). **אי אפשר לשחזר סיסמה שאבדה.**
- **נקה מהמכשיר:** מוחק את המסמך מהדפדפן בלבד.

### סרגל הקבצים (📁)
- **מסמך חדש** ובחירת שם, למשל תעודת הזהות של הלקוח.
- **תבנית:** מסמנים קובץ כתבנית. "➕ צור מסמך" יוצר עותק **נקי**: נמחקים תשובות, בחירות, חתימות, שורות כתיבה וערכי טבלה. נשארים כותרות, שאלות ואפשרויות. התבנית עצמה לא משתנה.
- **סיימתי:** הקובץ יורד כ-`.txt` ונעלם מהרשימה (נשאר בדרייב, ואפשר להחזיר אותו עם "הצג גם קבצים שהושלמו").
- **רענון:** כבוי / דקה / 2 דקות / 5 דקות, ו-🔄 ידני.
- **שמירה אוטומטית** לדרייב אחרי כמה שניות. אם שני מכשירים עורכים את אותו קובץ באותו זמן, האחרון שנשמר מנצח.

## 🔄 עדכון הפרויקט

**מ-ZIP (הדרך הרגילה):**

1. שמים את `site.zip` ליד `update_from_zip.py` בתיקיית העבודה.
2. מריצים בטרמינל: `python update_from_zip.py`. הסקריפט מוצא את תיקיית הפרויקט (או שואל), מעתיק את הקבצים וימחק את ה-ZIP.
3. ב-VS Code: **Commit** ו-**Sync Changes**.
4. מחכים דקה או שתיים, ומרעננים בחוזקה (**Ctrl+Shift+R**).
5. **בודקים:** ליד "נשמר אוטומטית" מופיע מספר הגרסה, ואין פס אדום בראש הדף.

> **פס אדום** אומר ש-`css/style.css` ו-`js/state.js` מגרסאות שונות (`--ver` ב-CSS מול `VERSION` ב-JS). מחליפים את שניהם מאותו עדכון.

הסקריפט לא מוחק קבצים שאינם ב-ZIP.

## 🛠️ פתרון בעיות

| בעיה | פתרון |
|---|---|
| `Error 400: origin_mismatch` | הכתובת ב-Authorized JavaScript origins לא זהה: `https://<משתמש>.github.io` בלי נתיב ובלי `/` |
| `Access blocked` | המייל לא ב-Test users, או שהאפליקציה לא פורסמה |

| כפתור ההתחברות לא פותח כלום | חלון קופץ חסום, יש לאפשר חלונות קופצים לאתר |

| קווים כפולים או עיצוב מוזר ב-PDF | `style.css` ו-`print.js` לא מאותה גרסה, מחליפים את הקבצים ומרעננים בחוזקה |
| פס אדום בראש הדף | אי-התאמה בין `style.css` ל-`state.js` |
| "המייל הזה לא מאושר" | המייל לא ב-`allowed.json`, או שהרישיון פג |
| קובץ לא נטען (404) | הקובץ לא הועלה, בדוק את `js/` ואת `index.html` |

## 🔒 פרטיות ואבטחה

- **אין שרת שלך.** המסמכים נשמרים בדרייב של הלקוח ובדפדפן שלו.
- **הרשאה אחת:** `drive.file`, כלומר רק קבצים שהאפליקציה יצרה.
- **מידע רפואי ורגיש:** באחריות הלקוח. מומלץ לא להזין פרטים מזהים שאינם הכרחיים.
- **חתימה** היא תמונה של חתימה ידנית, **לא** חתימה אלקטרונית מאושרת.
- יש להשלים את המקומות המסומנים בצהוב ב-`privacy.html` וב-`terms.html`, ולבדוק אותם מול איש מקצוע.
- אל תעלה ל-GitHub את תיקיית `admin`.
